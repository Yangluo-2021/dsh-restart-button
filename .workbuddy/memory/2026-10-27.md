### 本机环境的坑（下次发布必看）
1. **系统代理对 github.com 返回 502**（`127.0.0.1:58253`），但 `api.github.com` 正常。
   `gh` 登录和 `git push` 必须显式走 Clash：`HTTPS_PROXY=http://127.0.0.1:7897`。
   已在本仓库配了仓库级 `http.proxy`/`https.proxy` = 7897。**换机器要重配**。
2. `gh auth login --web` 的设备码输出被管道（`| head`）缓冲住，看不到码 →
   必须重定向到文件再读：`gh auth login ... > gh_login.log 2>&1`。
3. 本机 npm 默认源是淘宝镜像 `registry.npmmirror.com`（只读，发不上去）。
   已在项目根加 `.npmrc` 写死 `registry=https://registry.npmjs.org/`（只对本目录生效，
   不进 tarball）。
4. `gh` 原本没装，已用 `winget install GitHub.cli` 装（v2.103.3，路径
   `C:\Program Files\GitHub CLI`，不在默认 PATH 里，要手动 export）。
5. **自检脚本里的 DSH 路径是别人机器的**：`scripts/e2e.mjs` / `ui-check.mjs` /
   `panel-check.mjs` 的 `EXE` 常量 = `C:\Users\YSK\...`，本机是 `C:\Users\99687\...`，
   且 `AppData\Local\Programs\DSH Desktop` 是空目录 → 本机跑不了 e2e。
   （不影响发布。）
6. 本机 `~/.dsh/profiles/desktop/` 里没有装这个插件 → 发布后无法立即做

### 插件 id 语义（改包名时别搞错）
`cordis.patch.yml` 里：
- `id:` = 插件身份，必须等于 `lib/index.js` 的 `export const name` = `dsh-restart-button`（**永不改变**）
- `name:` = npm 包说明符 = `@877701572-wq/dsh-restart-button`（发布时变）

`scripts/prepare-publish.mjs` 只改 `name:`，不动 `id:` —— 这是对的。
它只替换 README 里的 `@NPM_USER/`，**不处理** `github:<GitHub用户名>` 那一处，
改完后要手动补。
